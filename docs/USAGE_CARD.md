# Карточка /usage: как настроить расход Grok API

Простыми словами: когда в Telegram вы отправляете команду `/usage`, бот показывает
лимиты подписки Grok и блок **API** — сколько денег и токенов ушло на Grok API.
Цифры берёт скрипт `bin/xai-usage` из Management API xAI. Для этого нужны
Management-ключ и ID команды. Обычный ключ для моделей (страница API Keys) не подходит.

## 1. Как получить Management-ключ

1. Откройте консоль xAI: [console.x.ai](https://console.x.ai) и войдите тем же
   аккаунтом, через который пользуетесь Grok API.
2. Откройте **Settings** (настройки) — это значок шестерёнки.
3. Не открывайте раздел **API Keys**: там создаются обычные ключи для моделей,
   они к биллингу доступа не дают.
4. Внутри Settings откройте вкладку **Management Keys** и создайте новый ключ.
5. Скопируйте ключ целиком сразу после создания. Обычно его показывают только
   один раз.

Ключ выглядит как длинная строка. Его нельзя присылать в обычное сообщение чата
и нельзя записывать в файлы репозитория. Его кладут в переменную окружения
`XAI_MANAGEMENT_KEY` (секрет на компьютере бота).

## 2. Где взять ID команды

ID команды — это не секрет, но в примерах ниже вместо настоящего значения стоит
заглушка `<TEAM_ID>`.

Его можно взять так:

- в тех же **Settings** откройте страницу настроек команды. Там указан
  идентификатор команды (Team ID) — длинная строка из букв, цифр и дефисов;
- или запросите проверку ключа:

```
GET https://management-api.x.ai/auth/management-keys/validation
Authorization: Bearer <XAI_MANAGEMENT_KEY>
```

В ответе будет поле `teamId`. Скопируйте его целиком.

## 3. Переменные окружения

Скрипт `bin/xai-usage` читает только окружение процесса и локальный файл.
В репозиторий ключ и ID команды не записываются.

| Что | Откуда |
|---|---|
| Management-ключ | только переменная `XAI_MANAGEMENT_KEY` |
| ID команды | переменная `XAI_TEAM_ID` (если задана, она важнее файлов), или локальный файл `xai-team-id` (его нет в git; образец — `xai-team-id.example`), или `~/.config/tg-bridge/team-id` |

В `env.example` эти имена указаны как комментарии, со заглушкой `<TEAM_ID>`.
Не вставляйте туда настоящий ключ.

Запуск:

```
/workspace/tg-bridge/bin/xai-usage
```

Если всё в порядке, скрипт печатает один JSON с `"ok": true` и полями для
карточки. Ключ в выводе не появляется. Если ключа или ID нет, или ключ
отклонён, скрипт всё равно завершается успешно, но с `"ok": false` и
пометкой `нужен management-ключ`, чтобы карточку лимитов можно было
отправить без блока API.

## 4. Запрос usage

Документированный адрес:

```
POST https://management-api.x.ai/v1/billing/teams/<TEAM_ID>/usage
Authorization: Bearer <XAI_MANAGEMENT_KEY>
Content-Type: application/json
```

Пример тела (не настоящие даты, только образец). `endTime` не входит в
диапазон (исключающая граница). Часовой пояс задаёт границы суток.

```json
{
  "analyticsRequest": {
    "timeRange": {
      "startTime": "2026-11-15 00:00:00",
      "endTime": "2026-11-25 00:00:00",
      "timezone": "Europe/Kiev"
    },
    "timeUnit": "TIME_UNIT_DAY",
    "values": [{"name": "usd", "aggregation": "AGGREGATION_SUM"}],
    "groupBy": ["unit_type", "description"],
    "filters": []
  }
}
```

В `values[].name` можно поставить:

- `usd` — расход в долларах;
- `units` — токены (для типов токенов) или другие единицы (картинки, мегабайты);
- `items` — позиции биллинга;
- `transactions` — число запросов.

Для каждого значения подходит только агрегация `AGGREGATION_SUM`.
Скрипт делает два таких запроса: `usd` и `units`. Оба группирует по
`unit_type` и `description`.

## 5. Что приходит в ответе

В теле ответа два поля верхнего уровня:

- `timeSeries` — список рядов. В каждом ряду:
  - `group` — значения группировки в том же порядке, что и `groupBy`
    (сначала тип токенов, потом название модели, например
    `["Prompt text tokens", "API OAuth grok-4.7"]`);
  - `dataPoints` — точки по дням. В каждой точке есть `timestamp` и
    `values` (массив чисел; при одном запрошенном значении смотрите `values[0]`).
- `limitReached` — если `true`, ответ упёрся в лимит строк и может быть неполным.

## 6. Важная тонкость с датой

`timestamp` — это момент полуночи запрошенного часового пояса, записанный в UTC.
Его нельзя обрезать как первые 10 символов строки.

Пример: точка с меткой `2026-11-21T22:00:00Z` при поясе `Europe/Kiev` (зимой
это UTC+2) — это **22 ноября** в Киеве, а не 21-е. Скрипт переводит метку в
`Europe/Kiev` и уже оттуда берёт календарный день.

## 7. Баланс предоплаты

Строка «Баланс: $…» на карточке **не показывается**. Кошелёк предоплаты в
xAI Console (запрос `GET …/prepaid/balance`) — это не тот остаток, который
виден на grok.com/dashboard как Credit balance. Чтобы не путать эти суммы,
карточка этот баланс не выводит. Скрипт `bin/xai-usage` может по-прежнему
запрашивать его, но в карточку это поле не попадает.

## 8. Как типы токенов попадают в таблицу

В карточке за последние 3 дня типы из API складываются так:

| Строка на карточке | Какие `unit_type` входят |
|---|---|
| **Ввод** | `Prompt text tokens` и `Prompt image tokens` |
| **Выход** | `Completion text tokens` и `Reasoning text tokens` |
| **Кэш** | `Cached prompt text tokens` |
| **Прочее** | всё остальное (картинки, хранение файлов и т.п.) — только в долларах, без токенов |

Итог по токенам — это Ввод + Выход + Кэш. В сумму долларов входит и Прочее.

## 9. Как выглядит карточка

Сверху по-прежнему лимиты подписки Grok (план, недельная полоска, «кто потратил
больше всего», дата сброса) и кнопка **🔄 Обновить**. Блок API идёт ниже.
Если ключа нет, блока API не будет (или будет короткая пометка), а лимиты
подписки всё равно придут.

Ниже — **пример** с выдуманными цифрами, не настоящий расход.

Пример блока API:

```
API
15.11 │            0.00
16.11 │            0.00
17.11 │            0.00
18.11 │            0.00
19.11 │            0.00
20.11 │            0.00
21.11 │            0.00
22.11 │ ██████████ 2.26
23.11 │ ███████    1.58
24.11 │            0.00

Ввод      1.3 млн    $1.37
Выход     0.1 млн    $0.33
Кэш      11.5 млн    $2.10
Прочее               $0.04

Итого за 3 дня: 12.9 млн токенов · $3.84
```

Что здесь видно:

- диаграмма за 10 дней: строка вида `ДД.ММ │ ██████████ 2.26`. Самый большой
  день занимает 10 клеточек, остальные пропорционально. Это моноширинный блок
  (`<pre>` в Telegram);
- таблица за последние 3 дня по типам токенов (миллионы токенов и доллары)
  плюс строка «Прочее»;
- итог за 3 дня;
- кнопка **🔄 Обновить** внизу карточки.

Текст карточки не длиннее 4096 символов — это лимит Telegram.
